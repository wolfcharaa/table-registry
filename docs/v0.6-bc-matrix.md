# `v0.6.0` compatibility matrix

[English](en/v0.6-bc-matrix.md)

Матрица фиксирует статус API `v0.5.x` перед добавлением generic select core. Consumer evidence собрано read-only
по реальному приложению 2026-10-04. Значение imports — число PHP import occurrences, а не число уникальных файлов.

Статусы:

- `keep` — contract остаётся самостоятельной частью библиотеки;
- `bridge` — observable contract сохраняется, implementation позднее делегирует generic core;
- `replace` — осознанная замена с migration evidence; в текущей matrix не применяется;
- `internal` — implementation detail без compatibility promise.

## Controlled-change rules

1. `bridge` never permits changing observable PHP/JSON/SQL behavior without a separate matrix update and test evidence.
2. A `replace` decision requires a reason, before/after mapping and migration of the real consumer in the same
   milestone.
3. Existing low-level types used by the audited consumer cannot be made internal merely because a cleaner replacement exists.
4. New generic APIs are added to `docs/public-api.md` only together with tests, docs/examples and bundled skills.
5. Final `v0.6.0` requires full legacy SQL/params/JSON parity and the two approved project pilots.
